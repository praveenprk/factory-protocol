The Factory Protocol

ContextOS builds itself on a production line. Every change is a batch with a work-order number (a WID). It travels through ten fixed stations in one direction, and each station is staffed by a single agent with a written job description. A shell script on the floor decides whether the batch may move to the next station.

Work in progress The Factory Protocol is still being strengthened. Content on this page may change as the protocol evolves.

01 · The line

Ten stations, forward only

Click a station to see who works it and what leaves it. The dashed red return path is the only way backwards: a move that is not on the routing sheet is refused and escalated to the governor.

02 · The line controller

A shell script decides, not a model

LLMs are non-deterministic, so the thing enforcing the gates has to be deterministic. The supervisor uses only shell, files, sha256sum and mv. Every transition request runs the same three checks.

  • factory/protocol/state-machineThe routing sheet. Ten FROM→TO lines. Anything not listed is invalid.
  • factory/protocol/agent-contracts/Work instructions per station: what the agent MAY do and MUST NOT do.
  • factory/supervisor.shThe line controller: create, transition, approve.
  • .factory/objects/<sha256>Content-addressed parts store. Each artifact is filed by its hash, so nothing changes after hand-off.
  • .factory/gates/<WID>/Where the batch is now (current-gate) and its transitions.log.
  • .factory/escalations/Deviation reports waiting for a ruling.
03 · Floor rules

How the stations stay honest

ONE BATCH, ONE STATION

Serialization

One agent, one gate, one commit sequence per WID. Parallel work only across separate WIDs that share no governance documents.

CLEAN ROOM · DECISION-019

Context isolation

Each agent reads only what its station needs. The test-agent never sees the code. The impl-agent never sees the design doc.

HAND-OFF PACKAGE

Artifact compression

Each gate's output is the whole input to the next. The next agent reads the SPEC, not the RFC it came from.

QC STATION

Adversarial critic

The critic-agent is scored on violations found, not on work approved. A commit needs a CLEAN verdict bound to the staged diff.

TRACEABILITY

Anchored commits

Every commit cites an RFC, SPEC, INV, V or DECISION number. Hooks reject anything else.

RECURSIVE

Self-applied

The factory is ContextOS's own governance model run on its own development. Only the protocol is committed. Runtime state stays out of git.

04 · Batch record

Gate records and review by exception

RFC-032 models gate records on the Electronic Batch Record. The core idea is review by exception: every step is recorded against an approved contract, and a human reviews only the deviations.

05 · Release

Where the human stands

DECISION-017 · 2026-05

Inspector at every station

The governor ran supervisor.sh approve <WID> before every one of the ten transitions. Nothing moved without a signature.

DECISION-039 · 2026-11

Review by exception

Gates advance on evidence recorded on the PR. The governor sees only deviations that need a ruling, plus the final release: the merge.
